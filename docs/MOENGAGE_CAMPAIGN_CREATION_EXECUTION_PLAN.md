## End goal and non-negotiable gate

Build a **separate** MoEngage campaign-creation feature: ingest a single brief or batch from Jira, CSV/XLSX, or JSON; construct Email/Push campaigns in the *selected* MoEngage workspace; save and read back each campaign as `DRAFT`; run non-sending validation; return draft IDs, validation issues, and a human handoff. **The agent never publishes, triggers events, changes active campaigns/flows, or sends test messages.** A human reviews and publishes in MoEngage. Do not confuse a locally labeled `DRAFT` staging summary with a persisted MoEngage draft. Keep this feature independent of Karix template whitelisting and separate Tata/Bajaj credentials, audience IDs, assets, and campaigns.

**Source of truth:** [source audit and live MCP discrepancy](MOENGAGE_CAMPAIGN_RESEARCH_NOTES.md) supersedes disputed claims in the older [specification](MOENGAGE_CAMPAIGN_CREATION_AGENT_SPEC.md). Recheck current provider schemas before a live write. Public [MoEngage V5 overview](https://www.moengage.com/docs/api/campaigns/campaign-draft-overview) documents Email/Push draft creation, read-only validation, and a *different V1 publish path*; draft-only is an enforced design, not an intrinsic MoEngage guarantee.

### Zero-cost rule (all phases)

**No incremental monetary spend is permitted.** Use existing local Python, Graphify, Ruff and deterministic parsing; do not add a hosted AI model, per-token TypeSafe/Gemini calls, new paid connector, new cloud service, paid plan, purchased credits, test send, segment-count job, or event trigger. Local offline fixtures and previews are the default verification path. Existing MoEngage/Jira/hosting subscriptions are not proven free: [MoEngage subscription documentation](https://www.moengage.com/docs/user-guide/settings/account/billing/manage-subscription) says products and add-ons are contract-specific, and [usage documentation](https://www.moengage.com/docs/user-guide/settings/account/billing/usage-details) describes billable usage. Public docs do **not** guarantee that draft writes/API requests are free in these workspaces. Before **any** live read/write that could have usage billing, the workspace billing owner must check **Settings → Billing → Subscription/Usage** or confirm the contract with MoEngage and record that the requested operations add **zero charge**. If this cannot be verified, keep the feature offline; do not reinterpret an unpriced operation as free. This constraint also applies to a future human publish, which is outside the agent's control.

### Phase 2 offline preview contract

- **Terms:** `account` is the canonical app tenant ID; `workspace_id` is the selected MoEngage workspace ID, **not** a permission grant. `source_ref` plus `row_id` identifies one input row, not a remote campaign. `preview_ready` means a locally complete **candidate**, never a persisted `DRAFT`.
