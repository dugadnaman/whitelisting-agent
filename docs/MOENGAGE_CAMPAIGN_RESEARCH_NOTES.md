# MoEngage campaign creation: official documentation audit

Researched 2026-10-01 against first-party MoEngage documentation and a read-only authenticated `tools/list` response from the Tata workspace's hosted MCP server. No campaign, event, template, flow, or test-send mutation was called. “Unsupported” below means **not supported by the cited documented/discovered surface**, not proof that no private or future endpoint exists. The claims audited are in [the existing specification](MOENGAGE_CAMPAIGN_CREATION_AGENT_SPEC.md).

### Authenticated MCP metadata: documentation differs from the live tool schema

Read-only `initialize` and `tools/list` requests to `https://mcp.moengage.com` using the existing **Tata** authorization returned server version `1.30.0` and 112 tools. Its `create_campaign_draft` declares `channel: PUSH | EMAIL | SMS | MMS` and describes new campaigns as `DRAFT`; `validate_campaign_draft` describes a no-mutation `DRAFT_PUBLISH` dry run. `patch_campaign_components` is **not draft-restricted**: its description also allows some active campaign updates. The discovered tool set has no WhatsApp/RCS campaign-create or flow-create operation; `test_campaign_by_draft_id` and `test_campaign_inline` send real test messages. No `tools/call` was performed. The existing Tata token advertises `campaigns:read`; a tool being listed does **not** prove write permission. MCP feature flags and workspace entitlements are also unverified. Source: authenticated [MCP `tools/list`](https://mcp.moengage.com) metadata; discovery client at [`backend/moengage_mcp.py:553-558`](../backend/moengage_mcp.py), compared with the [public MCP guide](https://www.moengage.com/docs/user-guide/ai-and-intelligence/merlin-ai/moengage-mcp-server).

Before claiming an SMS/MMS draft feature, resolve the public/live discrepancy with MoEngage and verify the workspace's flag, permission, and real draft-only behavior under an explicitly authorized non-production test. Public V5 REST is a documented Push/Email-only path independent of this uncertainty.

## Draft-state and safety boundaries

- **V5** requires `channel` (`PUSH`/`EMAIL`), `campaign_delivery_type`, and `created_by` (email). Content, audience and scheduling are optional at create and may be added with `PATCH /v5/campaigns/{campaign_id}`. Its `201` example responds with `data.id` and `data.status: DRAFT`; do **not** supply `status: "DRAFT"` as though it were a documented required input. Submitted optional components are validated at draft-create/patch strictness, not necessarily full publish strictness. [V5 create contract](https://www.moengage.com/docs/api/create-campaigns/create-campaign-draft-v5), [V5 overview](https://www.moengage.com/docs/api/campaigns/campaign-draft-overview).
- **Full dry-run validation:** `POST /v5/campaigns/{campaign_id}/validate` reads the saved draft and performs `DRAFT_PUBLISH` validation without modifying content or status. HTTP `200` can mean `data.valid: false`; inspect `data.errors[]` (`field`, `issue`). The dedicated endpoint has no equivalent in V1. [Validate Campaign V5](https://www.moengage.com/docs/api/create-campaigns/validate-campaign-v5), [V5 overview](https://www.moengage.com/docs/api/campaigns/campaign-draft-overview).
- **Publishing is possible outside V5.** V5 currently does not publish; the official overview explicitly points to **V1 `PATCH /core-services/v1/campaigns/{campaign_id}` for publishing**. The hosted MCP does not expose campaign publish, and describes publishing from the dashboard. Therefore “draft-only” is defensible for a deliberately restricted V5-create/patch/validate or hosted-MCP draft workflow, **not** a global MoEngage/API property. Do not grant/use V1 publish or any send/test/status/event-trigger path in a strict draft-only agent. `test_campaign_inline` / `test_campaign_by_draft_id` and V5 test endpoints **send real test messages to selected users**, even though they are not public launches. [V5 overview](https://www.moengage.com/docs/api/campaigns/campaign-draft-overview), [hosted MCP guide](https://www.moengage.com/docs/user-guide/ai-and-intelligence/merlin-ai/moengage-mcp-server).
- Flow status changes (`pause`, `resume`, `stop`, `retire`, `archive`, `unarchive`) are **mutations** of existing flows, not draft construction, and stopping/retiring can be irreversible; flow event/business-event APIs are enrollment/trigger paths, not create-draft substitutes. [Flows overview](https://www.moengage.com/docs/api/flows/flows-overview), [MCP Flows tool listing](https://www.moengage.com/docs/user-guide/ai-and-intelligence/merlin-ai/moengage-mcp-server).

## Authentication, privileges, limits, workspace isolation

- V5 REST and the documented legacy Create API use **HTTP Basic Auth** with workspace ID as username and API key as password; V5 `MOE-APPKEY` is **optional**, not a required header. Select **Campaigns** API access: **View** for reads, **Create & Manage** for draft create/update, and **Create, Manage & Publish** for publishing. The least-privileged key for this scope is Create & Manage, never Publish. The V1 Create operation documents `MOE-PROJECT-CODE` as mandatory **if Portfolio is enabled**, so workspace/project routing must be verified rather than inferred from a customer name. [V5 authentication/permissions](https://www.moengage.com/docs/api/campaigns/campaign-draft-overview), [V5 create OpenAPI headers](https://www.moengage.com/docs/api/create-campaigns/create-campaign-draft-v5), [legacy Create Campaign headers](https://www.moengage.com/docs/api/create-campaigns/create-campaign).
- Hosted MCP URL is `https://mcp.moengage.com`; its **OAuth session is separate from dashboard login**, bound to the environment, workspace and role selected during authorization, lasting 30 days with a seven-day idle timeout; to switch workspace/environment **re-authenticate**. Access respects the user's role/create-manage permissions. The public guide does **not** establish the existing spec's asserted OAuth authorization server, exact scopes/PKCE/refresh mechanics, embedded `moe_bearer` JWT, or dashboard-token reuse; these are **unverified from official public docs and must not be a design dependency**. The MCP guide lists availability in DC01–DC04 only. [Hosted MCP authentication and Key Authentication Behaviors](https://www.moengage.com/docs/user-guide/ai-and-intelligence/merlin-ai/moengage-mcp-server).
- V5 create limits: **5 successful creates/minute, 25/hour, 100/day**, with hour/day rolling windows; separate request-rate ceilings are **5 requests/second, 25/minute, 100/hour**. Rejected on breach; do not treat the 100/day count as a request cap. V5 validate has separate **10 requests/second, 100/minute, 6,000/hour**. V5 create/patch requires `Idempotency-Key` UUIDv4; validate does not. Its `request_id` deduplication window differs by channel: Push 1 hour, Email 1 day following success. [V5 Create rate limits/OpenAPI](https://www.moengage.com/docs/api/create-campaigns/create-campaign-draft-v5), [V5 overview FAQ](https://www.moengage.com/docs/api/campaigns/campaign-draft-overview), [V5 Validate rate limits](https://www.moengage.com/docs/api/create-campaigns/validate-campaign-v5). Legacy Create has its own published create limits but **cannot be assumed equivalent in lifecycle safety**: [legacy Create Campaign](https://www.moengage.com/docs/api/create-campaigns/create-campaign).
- Keep Tata and Bajaj workspace IDs/API keys, MCP authorizations, assets, audience IDs and campaign IDs **separate**. The official MCP workspace binding and REST workspace-ID authentication support an explicit per-account routing design; public docs do not verify any particular local credential-to-customer mapping. [MCP authentication](https://www.moengage.com/docs/user-guide/ai-and-intelligence/merlin-ai/moengage-mcp-server), [REST authentication](https://www.moengage.com/docs/api/campaigns/campaign-draft-overview).

## Existing specification: confirmed / contradicted / unverified

- **Confirmed, narrowly:** §§1.3, 2.1, 6: V5 and hosted MCP can create Push/Email drafts and validate without publishing; Flows API lacks create; WhatsApp/RCS campaign creation is not in the documented V5/MCP create surfaces; the 5/25/100 successful-create quotas are documented. Dashboard guides demonstrate WhatsApp and RCS UI creation. [V5 overview](https://www.moengage.com/docs/api/campaigns/campaign-draft-overview), [MCP guide](https://www.moengage.com/docs/user-guide/ai-and-intelligence/merlin-ai/moengage-mcp-server), [Flows overview](https://www.moengage.com/docs/api/flows/flows-overview), [RCS guide](https://www.moengage.com/docs/user-guide/campaigns-and-channels/sms-mms-and-rcs/rcs/create-an-rcs-campaign).
- **Contradicted or disputed:** §2.1's MCP SMS/MMS claim conflicts with the public MCP guide but matches the live server's advertised `create_campaign_draft` channel enum; actual availability is unverified. §2.1 asserts a legacy V1 SMS create contract, but the identified legacy Create endpoint says Push/Email only (V5 overview separately suggests V1 SMS; the exact operation remains unresolved). §1.3 suggests `status: "DRAFT"` in create input and §§4/6 imply all five blocks are initially required; V5 instead returns DRAFT and requires just three top-level fields at creation. §3.2 implies `MOE-APPKEY` required for V5; official V5 marks it optional. §2.1's blanket “WhatsApp/RCS dashboard only” is supportable for the **documented campaign-creation APIs/discovered MCP**, not proof against every private integration. [MCP tool limitations](https://www.moengage.com/docs/user-guide/ai-and-intelligence/merlin-ai/moengage-mcp-server), [live MCP tool discovery](https://mcp.moengage.com), [legacy Create](https://www.moengage.com/docs/api/create-campaigns/create-campaign), [V5 overview](https://www.moengage.com/docs/api/campaigns/campaign-draft-overview), [V5 Create schema](https://www.moengage.com/docs/api/create-campaigns/create-campaign-draft-v5).
- **Unverified / needs correction before implementation:** §3.1 OAuth server/scopes/`moe_bearer`/dashboard JWT claims; §2.1 exact RCS read/search and RCS Settings API template-registration claims; §2.1 WhatsApp template-creation claims (distinct from campaigns); §§4.2–4.5 literal SMS payload and connector shape as a safe draft API; §6 a fixed dashboard deep-link format; §2.1 marketing percentages (“100%”), attachments, and every platform/template subfeature. Public docs establish neither these specific claims nor account entitlements. The V5 create schema also specifically notes `BROADCAST_LIVE_ACTIVITY` **not supported in the draft-based creation flow**, despite the general overview including it among Push delivery types; confirm the exact schema for each requested variant before promising coverage. [V5 Create schema](https://www.moengage.com/docs/api/create-campaigns/create-campaign-draft-v5), [MCP `discover_schema` guidance](https://www.moengage.com/docs/user-guide/ai-and-intelligence/merlin-ai/moengage-mcp-server).

**Practical conclusion:** A separate **Push/Email-first** draft assembly agent is supported by documented V5/hosted MCP capabilities, provided its callable operations and credentials cannot publish, update live campaigns, or send tests, and it verifies the selected workspace before any write. SMS/MMS need capability and safety confirmation despite the live MCP schema; WhatsApp/RCS/Flows cannot be placed in the same programmatic campaign-draft promise on these sources. Existing `backend/api.py:4705-4717` exposes an authenticated but unrestricted generic MCP tool call, and `backend/moengage_mcp.py:35-54` falls back to shared credentials: neither currently enforces a separate draft-only, account-isolated agent. No authenticated mutation was tested here.
